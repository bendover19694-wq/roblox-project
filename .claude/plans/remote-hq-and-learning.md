# Remote Agent HQ from the website, and a Roblox-smarter HQ that learns from mistakes

## Context
Agent HQ (also called Ro-Automation by the owner) runs on the owner's PC at 127.0.0.1:4317 (`tools/agent-hq`). The DV Enterprises site (`tools/lantern-cloud`, Render free, `https://roblox-project-v8ym.onrender.com`) has owner sign-in with password then authenticator code. The PC opens no ports. Goal 1: the owner, signed in on the site, can use the full Agent HQ app remotely. Goal 2: HQ's asset library and questions get Roblox-specific, and HQ learns from its mistakes.

Hard limits: `tools/agent-hq/server.mjs` <= 1417 lines (change lines, add none); `test/server.test.mjs`, `test/mcp.test.mjs` must not grow; roles brief size tests pass; no new npm deps (both packages); files < 500 lines; full `npm test` exits 0 in both `tools/agent-hq` and `tools/lantern-cloud`; fakes only, no real secrets or network in tests; no commit/push/deploy.

## T1 (exec-remote): remote access through an outbound long-poll tunnel
Cloud (`tools/lantern-cloud`):
- Env `TUNNEL_SECRET` (>= 32 chars). Tunnel endpoints exist only when it is set; auth `Authorization: Bearer <secret>` compared with `timingSafeEqual`; rate limited; no session cookie involved.
  - `GET /tunnel/next` holds up to 25 s and returns one pending request as JSON `{id, method, path, headers, bodyB64}` (headers only content-type, accept, last-event-id) or 204.
  - `POST /tunnel/reply/<id>` with JSON `{status?, headers?, chunkB64?, done}`: first call sets status and headers (only content-type, cache-control, content-disposition kept); later calls stream chunks (for SSE); `done: true` ends the response. Body limit per call 1 MB, total per response 16 MB.
- Owner session (not collaborator: 403) required for `/hq` and `/hq/*`: strip cookies and auth headers, queue the request with path = the part after `/hq` (default `/`), wait up to 30 s (SSE `GET /hq/api/events` stays open and streams, closed after 10 min), map the reply. If the PC has not polled in 40 s answer 503 with a clear page "Agent HQ on your PC is offline". POST/PUT/DELETE under `/hq` still pass the existing origin check. Responses under `/hq` get the cloud security headers but a CSP that fits the HQ UI (read the HQ `public/index.html` and views for inline style or script use; allow only what it needs, keep `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'none'`).
- Dashboard: an "Open Agent HQ" link for the owner only, with an online/offline dot based on tunnel last poll (`/api/state` gains `tunnel: {connected}` for the owner only).
PC (`tools/agent-hq`):
- New `remote-tunnel.mjs`: started by server.mjs (inside an existing line, e.g. the autoTimers block) when `<stateDir>/remote.json` `{url, secret}` exists. Loop `GET <url>/tunnel/next`; run up to 6 requests at once; each request: path must start with `/`, no `//`, no `..`, no scheme; forward only to `http://127.0.0.1:<own port><path>` adding `x-hq-token` from `<stateDir>/owner-token`; buffer normal responses (limit 8 MB) and send with one reply; stream `/api/events` chunk by chunk. If an HTML response contains the owner token, replace it before sending (the browser must never receive the owner token). Exponential backoff on errors, stop when the file is removed.
- HQ web UI under a prefix: `public/views/core.js` (and any absolute URL users: EventSource, images, view and css loads in `index.html`) use `BASE = location.pathname.startsWith('/hq') ? '/hq' : ''`. Locally nothing changes. If the UI needs the token client-side, make it work without it when served under `/hq` (the tunnel adds it).
- Tests (both packages): unauthorized tunnel polling 401, wrong secret 401, collaborator 403 on `/hq`, owner request round trip through a fake PC poller, SSE chunks streamed, offline 503, path traversal refused on the PC side, owner token scrubbed from HTML, BASE logic.
- README: setup (`TUNNEL_SECRET` in Render, `remote.json` on the PC) and the security model.

## T2 (exec-learn): Roblox-smart assets and questions, learning from mistakes
Read `learning-hooks.mjs`, `corrections.mjs`, `feedback.mjs`, `preferences.mjs`, `briefs.mjs` (readLessons, correctionsSection), `catalog.mjs`, `assets.mjs`, `knowledge.mjs` first.
- Mistakes ledger (`mistakes.mjs`, JSON in stateDir): when a gate FAILs, an owner verdict is reject/changes, or a task fails, record `{role, game, tags (keywords from title and reason), what, fix?, count, firstAt, lastAt}`; merge near-duplicates (same role and >= 60% tag overlap) by incrementing `count`. When the follow-up task passes, store the fix text on the entry.
- Briefs: replace "newest N lessons" with the most relevant lessons and mistakes for this task (keyword overlap with title and body, then count, then recency), still capped to today's sizes. A mistake seen 3+ times is shown as "Repeated mistake (n times): ... Do this instead: ..." at the top of the section. Owner corrections keep outranking everything.
- Reviewer and kid-tester briefs get the role-under-review's top 5 repeated mistakes as a checklist.
- Roblox asset library: add a Roblox Creator Store search to the catalog (public toolbox search API; verify the current endpoint and response shape from Roblox docs or DevForum before coding, use fetch with a timeout, no key needed; if no public endpoint works, document that and skip). Each result: asset id, name, creator, creator verified, asset type, vote ratio when given. Mark Creator Store models as untrusted: briefs and the librarian rule say free models may hide scripts; prefer meshes, images, audio and packages from verified creators; never insert a model with scripts without reading every script first; record source and licence. Rank results by: verified creator, type match, votes.
- Roblox-smarter questions: extend the "How to ask" rule so each option's description states its Roblox impact where it matters (phone performance or memory, Mild maturity, monetization policy, DataStore or server load, Studio steps), and creative pick-from-4 options cite their source (taste-skill variant, design-md brand, LihFolk pack, Creator Store asset id, Claude Design). Keep briefs under size limits by trimming elsewhere.
- Tests: ledger merge and count, relevance ranking, repeated-mistake line, reviewer checklist, catalog parsing of a fake Creator Store response and ranking, untrusted flag, brief rule text.
