# Anti-slop standard (every agent, every task)

Slop is work that looks finished but was not designed: generic, unreferenced, unverified. HQ rejects it at review. Before `hq_complete`, pass every check below and name the evidence for each in your summary.

## 1. Reference first, never invent from nothing
- Open the game's own docs first (they outrank every vault), then the standard for your craft in this folder, then `hq_knowledge_search` for the task. Name the notes and files you used in `hq_note`.
- Match the house references (Visual bar) and the game's Theme tokens. A new colour, font, size or style needs a written reason.
- Another game is evidence of structure, never a template to copy.

## 2. Specific beats generic
- Every claim has a number, a path or a source: "54 px tap target", "zone 2 accent #2EE6D6", "src/server/Services/Clips.luau:40". Words like "nice", "clean", "modern", "engaging", "polished" or "epic" are not evidence.
- One clear idea per screen, zone, model or system. If you cannot say it in one sentence, it is not designed yet.
- Exaggerate on purpose: scale contrast, one hero, one accent. Timid, evenly spread, same-size everything is the main sign of slop.

## 3. AI tells that fail review on sight
- UI and art: purple or blue-violet gradients by default, glows and neon on everything, gradient text, glassmorphism, emoji as icons, a drop shadow on every element, everything centred, "Lorem", "Item 1" or "Placeholder" text, fake stats or features the game lacks.
- World: even scatter of props, the same mesh in a grid, floating or wall-clipping parts, no focal point, every zone mid grey-green, default Baseplate lighting.
- 3D: timid proportions, straight parallel lines everywhere, unions of default bricks presented as final, no silhouette test.
- Writing: filler intros, recaps, "Certainly", "robust", "seamless", "leverage", em dashes in player text, walls of text a kid will not read.
- Code: dead code, TODOs shipped as done, client-granted value, magic numbers outside Config, copy-pasted blocks instead of one function, tests that only check wiring.

## 4. Verify, then claim
- Run the check that proves it (tests, Studio capture, phone viewport) and read its output before you say done.
- Placeholders are labelled as placeholders in the summary, never passed off as final.
- Say what you did not do or could not check.

## 5. Creative work: options before builds
- 4 or more genuinely different options with previews in one `hq_ask_owner`, each citing its source (taste-skill variant, design-md brand, LihFolk pack, Creator Store id, Claude Design artboard). Build only the pick.

Sources: LihFolk Vault V2 (CC BY 4.0): "Art-Direction Nitpicks - The Principles Behind Them", "World Composition and Set Dressing - Designed, Not Scattered", "Low-Poly and Stylized Modeling", "LihFolk UI Spec"; the owner's taste-skill and unslop rules.
